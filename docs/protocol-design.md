# 标准协议设计范围

[返回文档导航](README.md) · [架构设计](architecture.md)

本文用于整理后续协议设计的议题，尚不是可实现的协议规范。首版操作范围与交付安排见[首版范围与实施计划](roadmap.md)。

[Manager 详细设计](agent-manager-design.md)已明确 MySQL、Nacos 2.3.2 与 React 的技术方向，并提出实例直连 Nacos、Manager 订阅纳管的待确认方案；该文中的操作与字段示意不构成标准协议。

## 1. 设计边界

协议将在后续单独设计，本文不固定 API 路径、字段名称、消息结构、事件枚举、状态机或传输方式。

| 范围 | 后续需要解决的问题 |
| --- | --- |
| 服务接入 | Nacos 注册范围与认证、最小 metadata、执行实例标识与启动代次、注销与重连 |
| 能力描述读取 | 描述结构与版本、读取认证、多实例一致性、动态刷新、失败与过期；与实际协议能力分离 |
| 运行状态读取 | 后端就绪、新会话/新执行准入、观察有效期；不把注册健康等同于可执行 |
| 协议兼容 | 协议版本、实际能力声明、必选能力与可选扩展 |
| 路由订阅 | 完整视图、持久版本、观察有效期与时钟偏差、删除传播及失联恢复 |
| 会话管理 | 平台与原生会话的关联、实例绑定、工作区及恢复边界 |
| 任务执行 | 提交、状态、结果、超时与重复请求处理 |
| 执行事件 | 文本输出、进度、工具活动、事件顺序及断线后的处理 |
| 交互控制 | 取消、用户确认、补充输入及不支持时的处理 |
| 错误与扩展 | 错误语义、可恢复性、厂商扩展及兼容规则 |

统一协议描述对外语义，厂商差异由 Daemon 的适配器处理。第三方服务实现相同的必选能力即可接入，可选操作通过能力声明确定，不能假定所有后端都支持。
